# Data Structures and Algorithms with TypeScript

**Big O notation** describes how an algorithm's time or memory usage grows as the input size (`n`) grows. It helps us understand how well an algorithm can handle large amounts of data.

For example:

- `O(n)` grows with the input size.
- `O(log n)` grows very slowly, so it works well with large inputs.

Big O is commonly used to describe the **worst-case performance** of an algorithm.

**Big Omega (Ω)** describes the **lower bound** of an algorithm. It tells us the minimum amount of work an algorithm needs to do. For example, an algorithm that is Ω(n) needs at least work that grows with `n`.

**Big Theta (Θ)** describes the **exact growth rate** of an algorithm when its upper and lower bounds grow at the same rate. For example, if an algorithm is Θ(n), its work grows linearly with the input size.
